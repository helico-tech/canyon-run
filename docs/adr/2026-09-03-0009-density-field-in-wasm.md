# ADR 0009 — The chunk density field runs in wasm, bit-identical, with the TypeScript field as the fallback and the oracle

## Context

Research 03 measured a 2.9× speedup for the field in wasm with bit-identical
output. Two JavaScript workers keep up today (`docs/context/performance.md`);
the headroom would buy richer octaves or wider halls. The field is already
transcendental-free (ADR 0002, ADR 0004): only + − × ÷ sqrt floor abs and
32-bit integer hashing, so a port can be exact.

## Decision

- A Rust crate (`wasm/field`, no dependencies, no allocation, no imports)
  ports the per-sample hot path: the noise, the biome density assembly, the
  feature and tunnel distance functions, and the shell skip of a chunk row.
  It exposes static buffers and `fill_row`; the host writes blended
  parameters, spines, feature records and a row descriptor per row.
- TypeScript keeps everything per row: biome blending, difficulty scaling,
  spines, feature gathering. `src/terrain/wasmField.ts` mirrors `fillGrid`
  row by row.
- Exactness rules in the port: wrapping 32-bit arithmetic for hashes,
  JavaScript's `Math.max`/`Math.min` semantics for signed zeros, identical
  operation order, no fused multiply-add (Rust does not contract by default).
- The TypeScript field stays the oracle and the fallback: a differential
  test fills chunks in every biome with both and requires byte-identical
  grids; the worker uses wasm once it has loaded and TypeScript before that
  or if loading fails. Chunk output is a pure function of (seed, chunk, mode)
  either way.
- The build product `public/field.wasm` is generated by `pnpm build:wasm`
  (cargo, wasm32-unknown-unknown) and is not committed; CI adds the target.

## Consequences

- The sim keeps using the TypeScript field on the main thread (collision,
  HUD probe): same numbers by proof, no wasm on the sim's critical path.
- Any change to the field must be made twice; the differential test fails
  the check until both agree, which is the intended ratchet.
- Contributors need a Rust toolchain for `pnpm check`; the README says so.
