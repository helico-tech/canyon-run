# 0003: Headless validation — replay-driven runs, semantic pixel gates, golden hashes

## Context

The agent building this game cannot watch a screen. It needs to run the game
headless, drive it with known inputs, capture frames, and decide whether the
render is right. Measurements on this machine
(`docs/research/2026-09-03-02-headless-validation.md`):

- Playwright Chromium renders WebGL2 with no flags (ANGLE → SwiftShader). Frame
  hashes are identical across runs and across chromium / headless-shell / Chrome.
- Throughput is validation-grade, not real-time: ~60 ms per frame for 100k
  triangles at 720p, ~33 ms at 640×360. A 300-frame run with ten PNG dumps takes
  10–20 s.
- `canvas.toDataURL` costs ~12 ms, `page.screenshot` ~100 ms, and returning a
  raw pixel array through `page.evaluate` costs seconds (never do it).

## Decision

1. **Test mode.** With `?test=1` (or an injected `window.__replay`) the game does
   not start a rAF loop, uses the fixed tick, requests no pointer lock, and creates
   the WebGL context with `preserveDrawingBuffer: true`. It exposes
   `window.__game` with `step(n)`, `state()`, `setInput()`, `frameHash()`,
   `readPixel(x, y)`, `dataURL()`, and `window.__info.renderer`.
2. **Replay-driven runs.** A headless runner (`tools/headless/run.ts`) loads the
   built game in Playwright, feeds a replay file, steps the sim at fixed dt, and
   writes `frames.jsonl` (`{frame, state, hash}` per frame) plus a PNG every N
   frames and a labelled contact sheet.
3. **Gates, in order of trust:**
   - Sim state hashes must match the golden replay always.
   - Semantic pixel checks are the default render gate: sky probe in the top
     band, non-sky in the bottom band, HUD anchor colours, sky fraction within a
     range, unique-colour count above a floor, edge density bounded, temporal
     change while moving, and zero console errors after filtering the known
     SwiftShader ReadPixels warning.
   - Frame hashes are compared exactly only for the same renderer string;
     goldens are stored keyed by renderer and regenerated by a script, never by hand.
   - Perceptual diffs (`pixelmatch`, max diff ratio 1 %) cover HUD layout and a
     few hero frames, not every frame.
4. **Agent review.** The agent reads the contact sheet PNG with one file read;
   full-res frames only when the sheet looks wrong. Validation runs at 640×360
   unless a check needs full resolution.
5. **Before/after discipline.** Every user-visible change runs the same replay
   before and after; state must match unless the change is to the sim, hashes must
   match unless the change is visual, and both contact sheets are read.

## Consequences

- One replay format drives Node validation, browser tests, and agent runs.
- Performance is never gated on frames per second in this VM (±40 % noise).
- A Playwright or Chromium upgrade may change SwiftShader output; goldens are
  re-baselined deliberately in a commit that says so.
